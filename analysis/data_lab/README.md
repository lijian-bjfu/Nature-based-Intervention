# 数据实验

## 原则：先研究，再整理

data_lab 是探索性工作。要解决哪些问题、解决多少，是在工作中逐步生成的，事先无法确定，所以这里叫 Lab。文件夹不预先建立：出现一个问题，就为它建一个文件夹；做完后在本文末尾的清单里总结。

## 文件夹的组织

三级：pipeline ／ 环节 ／ 研究问题。

**第一级 pipeline**：按数据类型，也就是实验对象划分：track（虚拟自然中的行为）、psycho（问卷）、physio（生理）。

**第二级 环节**：数据工作的阶段。环节文件夹在出现这类问题时才建。

- processing（数据处理）：清理、转换、切分等，把原始数据变成可用的数据。
- description（数据描述）：根据分布、均值、方差等数据特征，识别数据本身的特点，探索数据之间的关联，包括识别行为的分类方式、为定义指标找阈值。描述是为了认识数据的样子，不做推断。
- statistics（统计分析）：基于统计方法探索、检验变量之间的关系。可以只用一类数据（如埋点内部），也可以结合问卷、生理等数据。
- report（报告）：把探索结果整理成供报告、论文使用的图表与文字。

**第三级 研究问题**：一个文件夹对应一个问题，按问题命名，例如 description/base（原始记录的基本描述）、description/behavior（行为的分类方式）。一个环节下有几个问题、叫什么，随工作进展而定。每个问题文件夹下不再预设子目录：

- 本问题用到的**脚本**直接放在该文件夹下。
- **README.md**：写给研究者的说明，包括：要处理什么问题；这些工具怎样帮助回答这个问题（哪个问题看哪张图、哪个表）；每个脚本做什么、哪个是运行入口；怎么运行、每个参数的含义和可选值；结果里每个文件展示什么；结论。问题、工具、参数、结果说明开始时就写，结论在探索结束后补。样板见 track/description/base/README.md。
- **log.md**：研究过程日志——每次有进展时记下试了什么、为什么试、看到了什么、下一步打算。写给人读，不是程序流水。
- **results/**：最近一次运行的结果，每次运行覆盖，不按时间建文件夹。报告写给研究者读：先写发现，再附表和图。
- **save/**：研究者认可、要保留的结果，手动从 results/ 复制进来，按含义命名（如 save/清理方案A/）。它是日后晋升的依据。

**研究者只看 data_lab。** 每次实验的结果都在所在问题文件夹的 results/ 或 save/ 里留一份，日后检索只在这里找。项目 data/（processed、final）由 Claude 维护，研究者一般不进去；正式制表生成的表也要复制一份到对应问题的 save/，并附说明.md 写明来源、数据与生成日期。
- 每次运行的参数、Git 提交号等追溯信息自动写在 results/_provenance/，平时不用打开。

results/ 与 save/ 只存本机，不入库；脚本、README.md、log.md 入库。

## 归类原则

- 先按数据类型定 pipeline，再按工作目的定环节，最后按具体问题建文件夹。
- 环节按**目的**判断，不按所用方法判断。例如用了 Otsu 分界、双峰系数这类统计方法，但目的是认识数据的形状、找分类方式，仍归 description。
- 新建环节或问题文件夹前，先与研究者确认归类。

## 待梳理

问题是生成式的、动态增长的，现有组织方式还只是起点。处理几个问题之后，总结经验和规律，再回头梳理 data_lab 的组织机制（文件夹层级、命名、问题之间如何共享工具等）。在那之前按本文的方式执行。

## 晋升

探索中确认的方法或指标，经研究讨论后：定义写进研究文档（埋点指标写进《研究思路/实验记录-埋点.md》）并登记到 global_settings.py 的 METRICS；计算代码移到 analysis/tools/，供 table_flows 调用。save/ 中保留支持这次决定的结果。

## 其他约定

实验只复用 global_settings.py 中的原始规范和已确认指标定义，不读取 table_flows 参数。参数写在入口脚本顶部 PARAMETERS，保存后在 VS Code 点 Run。清理、格式化等供后续使用的数据放项目 data/.../processed，最终分析表放 data/.../final。

活跃脚本的 SCRIPT_HISTORY 保留带时区的创建或重要修改记录；analysis/tools/lab_history.py 可按时间检索（生成的 history_index.csv 只存本机）。
