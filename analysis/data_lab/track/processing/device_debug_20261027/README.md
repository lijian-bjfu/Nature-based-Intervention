# 10-27 真机测试：从旧版调试日志近似还原埋点

## 一、问题

10-27 第一位外部被试在 iPad 上测试时，装的是 10-17 导出的旧版本（10-27 打包因真机编译错误失败），没有正式埋点七张表，只有调试日志。这里回答：这些日志能还原多少埋点内容，能否画出路径浏览页、算出《实验记录-埋点》第十节的指标。

还原出的记录是**近似数据**，只用于检验与观察，不进入任何正式分析。

## 二、还原方法

原始日志在 `data/pilot_and_test/test/raw/device_debug_20261027/`（说明见其中的 说明.md）。用到三份：点击日志、声音日志、剧本事件日志（18:28 那一场，主体验，920.6 s）。

- **点击日志的行要先分开**：旧版 StopOnLook 下，每次拖屏开始都会写一行"停下来"（拖动时在走）或"停下来·空停"（拖动时站着）。这 173 行是**拖动**，不是点击。"补发出手"回填到原点击的"是否触碰"，"后退"是长按后退。真正的点击 304 次。
- **位置样本**：点击日志每行和声音日志每行都记了相机位置与左右朝向（鸟叫、蛙声、脚步、换地面都有），合起来约 1090 个样本，间隔中位 0.63 s、最长 7.9 s。
- **时空表**：两个样本之间有位移时，假定从前一样本起以 0.78 m/s 走过去、到了就停；朝向取前一个样本。俯仰与脚下地面高度没有，留空。
- **环视表**：只能还原拖拽式。起点是拖动那一行，终点取下一次触屏之前的最后一个朝向样本；转动量按样本累加，是下限。上下转动没有。
- **世界事件**：剧本事件的发生 / 未发生；手惊飞常驻生物旧版不记。
- **技术故障**：声音日志的卡顿行，按规范只记 ≥ 0.5 s 的；旧版没有切后台记录。
- 空气墙没有阻挡类型，受阻原因记为 `BarrierUnlabeled`。

## 三、每项指标的可信程度

| 指标 | 程度 | 说明 |
|---|---|---|
| 10.4 点击量、10.7 approach、10.8 触摸、10.9 首次触摸、10.10 触摸过的景点、10.11 长按后退 | 精确 | 直接来自点击日志 |
| 10.5 无位移点击 | 基本精确 | 起步受阻、没打中精确；"点地没动"用重建轨迹判断 |
| 10.12 环视次数 | 精确用日志：站着拖动 120 次 | 制表按重建轨迹判断"开始时是否在走"，得 125，偏高；以日志的 120 为准 |
| 10.12 环视量 | 左右为下限，上下缺失 | |
| 10.1 停留与行走 | 粗略 | 样本间隔约 0.6 s，2 s 级的停顿切不准 |
| 10.2 逗留、10.3 行动范围、10.6 景点到访、区域时间 | 近似，较稳 | 15 s / 3 m 的尺度对采样粗细不敏感 |

另外，地理空间标注是现在的版本，10-17 版的空气墙与场景可能略有不同，区域、景点归属只作参考。

## 四、怎么运行

在 VS Code 打开 `reconstruct.py`，点 Run。参数在顶部 PARAMETERS（日志文件、开始时刻、假定步速），一般不用改。
