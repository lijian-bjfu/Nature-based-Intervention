# 埋点原始记录的描述

## 问题

APP 记录下来的原始数据（七张表，规范见《研究思路/实验记录-埋点.md》附A）实际是什么样子：每张表是否齐全、记录了哪些行为、这些行为在时间和空间上如何分布。这是设计埋点指标之前的基础工作：先看清原始记录能捕捉到什么，再决定指标怎么定义。

这里只描述事实，不定义新的行为指标，也不把行为解释为兴趣、注意、无聊或动机。

## 方法

入口 `track_describe.py`（参数在文件顶部 PARAMETERS，保存后在 VS Code 点 Run）。依次执行四步，各步脚本都在本文件夹：

1. `track_inventory.py`：核对每场会话的文件是否齐全，区分"文件不存在"和"文件存在但没有行"。
2. `track_clean.py`：在副本中处理已确认的历史取值（早期数据中的 None 转为 NoHit / NotBlocked），原始数据不改动。
3. `track_format.py`：统一类型；出现规范外的取值时记录下来，并附上产生该数据的 APP 代码版本（app_commit）。
4. `track_describe.py` + `track_report.py`：生成每场会话的描述表、三张图（空间分布、时间分布、操作）和报告。

`experiment.py` 负责参数校验和各步的调度。
