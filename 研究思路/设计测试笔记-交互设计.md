当前的交互设计在实验环节测试起来很别扭，也说不出来是哪别扭。本文档就记录相关的测试体会与反思。

当前交互设计主要包含【我想去】、【我想看】、【我想摸】三个交互环节。

## 基于 Mask 的划分

目前 [TapMoveCamera_V5.cs](/Users/lijian/Working%20Projects/NBI%20proj/nature/Assets/_Project/Interaction/Avatar%20Camera/TapMoveCamera_V5.cs) 在处理3个环节时的技术方案是依赖于Mask来区分世界物体，会划分在哪个交互环节。现在这些 Mask 与三种意图的并非一一对应，而是几个可以交叉组合的控制维度：

| Mask | 实际职责 |
|---|---|
| `Tap Ray Mask` | 对象能否被点击射线命中，是所有回应的总入口 |
| `Browse Layers` | 命中后保持平视；不在其中的层默认进入聚焦 |
| `Walkable Mask` | 表面是否可能被判定为“可以站上去” |
| `Blocking Mask` | 路径是否被绝对阻挡 |
| `Approach Layers` | 对于不能站上去的目标，是否走到 `Touch Keep Distance` |
| `Viewing Layers` | **当前没有被代码实际使用** |
| `Rigid Touch Layers` | 哪些层触发刚性触摸 |
| `Water Touch Layers` | 哪些层触发水面触摸 |
| `Foliage` | 通过硬编码层名触发柔性触摸，没有独立 Mask |

## 对点击的回应

### 1. “点击它以后怎么看”

由 `Browse Layers` 决定：

- 在 `Browse Layers` 中：浏览，保持平视；
- 不在其中：聚焦，把俯仰锁在点击命中点；
- 左右转身不由它决定，浏览和聚焦都可能转身。

当

```text
Browse Layers = Terrain, Rock, Road
```

表示：

- `Terrain`、`Rock`、`Road`：浏览；
- `DeadWood`、`Foliage`、`Water`、`TouchRock` 等如果不在 Browse 中：聚焦。

因此当前普通 `Rock` 是浏览对象，并不是聚焦对象；`TouchRock` 则很可能是聚焦对象。

---

### 2. “点击它以后往哪里走”

主要由 `Walkable Mask`、`Blocking Mask`、坡度和 `Approach Layers` 共同决定。

#### Walkable Mask

这一层仅是判断哪些层的物体可以走上去，但是否能走上去另说，比如当：

```text
Walkable = Terrain, Rock, DeadWood
```

被点击表面如果在这里，并且坡度不超过限制，会被判为 `WalkTo`。这种情况下优先使用 `walkKeepDistance`：

```csharp
float keepDistance =
    (intent == TapIntent.WalkTo) ? walkKeepDistance
  : approach                     ? touchKeepDistance
                                 : viewingDistance;
```

见 [TapMoveCamera_V5.cs:2460](/Users/lijian/Working%20Projects/NBI%20proj/nature/Assets/_Project/Interaction/Avatar%20Camera/TapMoveCamera_V5.cs:2460)。

这意味着：

**只要命中表面被判定为 WalkTo，`Approach Layers` 就不会决定停下距离。**

例如：

- 点 `Rock` 的平缓顶面：可能是“走上去”；
- 点 `Rock` 的陡峭侧面：坡度太大，变成 `LookAt`；
- 点 `DeadWood` 也是根据具体命中面的坡度决定。

#### Blocking Mask

限制哪些地方不能走。比如当：

```text
Blocking = EnvBarrier
```

意味着：

- 点击到阻挡层，目标被判为不能站；
- 行走路径采样碰到它，也会停止前进。

#### Approach Layers

他表示是否需要走到对象跟前，类似于当走不到一个对象的时候，还要不要走过去，而该决定要结合最终距离物体有多远来综合判断。例如当：

```text
Approach = Water, Foliage
```

它表达的是：

> 当目标不是可站立的 `WalkTo` 表面时，要不要走到跟前。

所以：

- `Water`、`Foliage`：走到 `Touch Keep Distance = 0.5m` 附近；
- 其他不能站立的目标：停在 `viewingDistance`；
- 它本身不等于“我想看”，更接近“为了能够触碰而靠近”。

---

### 3.  “点击后停在哪里看”

该行为本该是由 Viewing Layers 来管理。其设计的功能：

> 打中这些层 → 停在 viewingDistance 处

然而它最终并没有放到交互系统中。仅把这个概念在代码里留下来了。因此但整个代码里除了声明和注释外，没有读取它：

```csharp
public LayerMask viewingLayers;
```

实际判断只有：

```csharp
bool approach =
    (approachLayers.value & (1 << hitLayerIdx)) != 0;
```

然后逻辑是：

```text
是 WalkTo       → walkKeepDistance
否则在 Approach → touchKeepDistance
否则            → viewingDistance
```

所以当前真实行为是：

- `Approach Layers` 中的非 WalkTo 目标：靠近；
- **所有其他非 WalkTo 目标**：远观；
- `Viewing Layers` 勾什么或不勾什么，目前都不会改变行为。

因此 Inspector 中的 `Viewing Layers = Nothing` 不是“当前没有我想看对象”，而是这个字段目前实际上不起作用。之所以留下这个空当，我回忆不起来具体的原因了，但是我猜大概率是现在的停下来的机制已经足够复杂，本身 Approach Layer 都没处理好，所以Viewing Layer 加进去会导致逻辑更加混乱，所以这个地方留了一个缺口。

---

### 4. “点击后它能不能被摸”

由三条独立通道决定。

#### 柔性植物触摸

注意 **植物柔性触摸目前没有独立暴露为 LayerMask。** 代码直接查找名字必须恰好为 `Foliage` 的 Layer：

```csharp
private bool IsFoliage(int layer)
{
    cachedFoliageLayer = LayerMask.NameToLayer("Foliage");
    return layer == cachedFoliageLayer;
}
```

见 [TapMoveCamera_V5.cs:2825](/Users/lijian/Working%20Projects/NBI%20proj/nature/Assets/_Project/Interaction/Avatar%20Camera/TapMoveCamera_V5.cs:2825)。

因此：

- Layer 名必须是 `Foliage`；
- 有 Collider；
- 在 `Tap Ray Mask` 中；
- 距离足够近；
- `IndicatorHand` 判断可达；

才会触发柔性触摸。这是个大问题，对未来的维护造成了很大的困难。后续必须修改。

#### 刚性触摸

相对于柔性触摸，刚性触摸要简单很多。例如当：

```text
Rigid Touch Layers = DeadWood, TouchRock
```

这表示这两个 Layer 在距离足够近时，调用刚性触摸动画。

#### 刚性触摸与柔性触摸的本质差异：

**Rigid Touch 只表示“近处点击时允许摸”，不保证系统会主动走近。** 换句话说，刚性触摸距离优先，触摸对象排在其后。距离到了，自然就能触摸。而柔性触摸，对象优先，距离其后，锁定对象后，距离要不断地找补，以满足触摸的结果。这个设计是有意的，它意味着在刚性触摸下浏览模式优先，不会因为在很远的地方点击到倒木（刚性触摸对象），就把它变成了【我想摸】的对象，摄像机仍然处在【我想去】模式，镜头不会上下摇晃。然而当触摸了柔性物体后，【我想摸】的模式则被触发。摄像机会旋转，把该物体放到视野中心并锁定该物体为前进目标。摄像机和要摸对象之间的距离，服务于我想摸这个动作。因此代码里还加入了approach layer 这么一层对象，即使面对够不到的东西也试图让摄像机再往前凑一凑、够一够。但最终，由于还有手够得到够不到这一层，所以这一个凑一凑的环节并不一定能生效。

例如，当 `Approach Layers` 里没有 `DeadWood` 和 `TouchRock`。因此实际可能出现：

- 目标可以聚焦；
- 目标具有刚性触摸资格；
- 但系统停在较远的 `viewingDistance`；
- 手最终因为够不到而拒绝触摸。

如果希望 `TouchRock` 和 `DeadWood` 都具有“点远处先走近、到跟前再点即可摸”的完整行为，它们通常也应该进入 `Approach Layers`。不过 `DeadWood` 同时在 `Walkable Mask` 中，其平缓表面仍会优先按 `WalkTo` 处理。

但是对于柔性物体而言，这个approach layer 似乎除了增加交互的难度之外，没有什么其他价值吧？因为最后的判断仍然取决于手够得到够不到。

#### 水触摸

对水的触摸单独处理，例如当：

```text
Water Touch Layers = Water
```

这是单独的第三种触摸回应，手会进入水面下方，而不是停在 Collider 表面。



## 总结

### 回顾总体目标

本研究的基本假设是可互动的虚拟自然比基于自然暴露的虚拟自然在恢复（认知与情绪）效果上更好。

### 表面的待优化点

1. Viewing Layer 到底该如何处理和使用？
2. Approach Layer 真正的价值到底是什么？存在的意义是什么？该设计针对的交互情境是什么？如果不能很好的回答上述问题，该机制需要简化或删除。

### 设计思路在技术上的实现路径

当前场景中各 Layer 可大致整理成：

| Layer/对象 | 视线 | 移动 | 触摸 |
|---|---|---|---|
| Terrain | 浏览 | 可走 | 不摸 |
| Road | 浏览 | 是否可走取决于是否也在 Walkable；截图中不在 | 不摸 |
| Rock | 浏览 | 平缓表面可走，陡面远观 | 当前不属于刚性触摸 |
| Foliage | 聚焦 | 主动靠近至 0.5m | 柔性摸 |
| Water | 聚焦 | 主动靠近 | 水触摸 |
| DeadWood | 聚焦 | 平缓表面可走；其他面默认远观 | 近处可以刚性摸 |
| TouchRock | 聚焦 | 不在 Approach 时默认远观 | 近处可以刚性摸 |
| EnvBarrier | 通常不能作为目的地 | 阻挡路线 | 不摸 |

按照最初的【我想去】【我想看】【我想摸】三种交互意图梳理上述对象。他们与被试的互动模式大致如下

1. 【我想去】体现在 **视线回应**：`Browse / Focus`，与 **空间回应**：`Walkable / Blocking / Approach / 默认远观`
2. 【我想看】体现在  **可点击性**：`Collider + Tap Ray Mask`
3. 【我想摸】体现在 **触觉回应**：`Foliage / Rigid Touch / Water Touch`

### 深层的待解决问题

对实验的潜在影响可能在于”被试可能把注意力花在理解系统，而不是自然上“。这涉及到环境中哪些地方是限制，哪些地方可以探索。但这一问题属于”涉及测试笔记-场景设计.md"部分，这里先按下不表，主要考虑第二个后交互方面问题，即”一个简单的点击，承载着太多的交互意图“，“两种手势”是实现低负担的手段，不是低负担本身。 有两个手势但十种隐藏后果，可能比三个含义稳定的操作更费力。两种手势是天然的无法支持三种意图，还是会存在某个最优解决方案，然而当前的设计模式设计有缺陷无法达到这一效果。目前项目进度已经不允许从根本上推翻当前的交互模式了，只能假设的确会存在一个更优的解决方案，尽可能的往深入挖掘和探索。

## 反思与下一步工作内容

当前的事件回应分类方式过于粗暴，仅通过 Mask 层来处理。后续可能要考虑把事件对象分类进行进一步的细化。以对象为单位来触发我想去、我想看或我想摸的意图。在检查对象的同时，还应该看该对象周围的环境，它是否与摄像机是跨区域（R1-R4）、植物的密度、附近是否可以有站立的空地等信息。这些信息可用于进一步区分我想去和我想看的意图。

调整各交互规则之间的权重。

世界限制为最高等级。陡坡和 EnvBlock 层是最高限制。任何意图受阻后，都要停在可达位置，不能越过世界限制。

浏览为第二高等级。点击后即前往该位置，误差来自身体尺寸和停止精度。将更多的点击归为【我想去】的意图。点击地面道路以及任何非触摸层都默认为浏览模式，点击超过一定距离的物体，也是浏览模式。点击植物密度很高的位置，也是浏览模式。点击射线触碰到Block层也是浏览模式。目标点附近无法站人，也是浏览模式。即使点击到非Browser层的实体，首先也是请求接近命中位置，而不是根据该点击来推断被试一定是想观察或触摸。

【我想看】和【我想摸】的对象，处于第三等级。这两个交互行为同时发生。区分二者的是手是否够得到。够不到的是【我想看】，够得到的就划为【我想摸】。该等级交互只有在距离足够近后才会触发。

减少距离判断的标准。摄像机与对象是否足够近和手是否够得到，现在来自两套判别依据。应消除这种技术性矛盾。但这不代表每个可触对象都必须从所有方向摸到；隔着溪流摸不到仍然可以是合理的世界限制。
