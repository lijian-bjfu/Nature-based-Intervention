# 研究方案第八轮

> 本轮从"双屏原型该用什么技术栈"这个工程问题入手，意外地把第七轮悬而未决的研究问题归属问题逐步推到了收口。本轮的核心产出有三层：(1) 在方法论层面认领了 package / artifact-centered 路线，并识别出贯穿前七轮的一个根本性思维习惯——"为某个设计特征寻找剥离式对照"的本能（即第七轮命名的"反噬"机制），正是七轮无法定稿的总开关；(2) 在研究问题层面，把灵魂动词从"导致/腾出"（因果转化）降到"改变/伴随"（描述性机制），从而让 package 两臂设计与样本量（约 70 人）与研究问题首次对齐；(3) 在工具层面，确定 MVP 形态与技术栈（全网页栈，非 MPC），并明确原型的唯一任务是回答"咬合机制在体验里是否存在"，进入"指头戳屏幕"阶段。

---

## 本轮的触发点

第七轮（2026-05-19）以一次结构性反思推翻了第六轮"进入原型阶段"的判断，明确"方案的结构性问题没解决前，做原型只会把不对齐转移到工程层"，并把实验启动、pilot、双 iPad 开发全部推迟，要求"继续做分析验证"。

第八轮的入口是一个纯工程问题：双屏曼陀罗原型该做 iOS app 还是网页、自然屏是否该用游戏引擎。但这个问题被快速识别为"超前"——因为第七轮的研究问题尚未立住。于是对话从工具选型，被反向牵引回研究问题本身，并在一连串自我反驳与拆解中，把第七轮的四个未决问题（A 措辞、B 自然身份、C 结局变量、D defence 路径）实质性收口。

## 推理链条的核心步骤

### 步骤 1——原型的两种性质：逃避式 vs 生成式

第七轮反对的"做原型"，是"研究问题没立住就做工程、用工程进度冒充研究进展"的**逃避式原型**。本轮要做的，是"用做东西来产生还没有的判断"的**生成式原型**——因为剩下的几个未决问题（独立干预 vs 组合、自然是哪个身份、咬合是设计还是变量）都不是"哪个答案对"的问题，而是"我到底想要哪个"的问题，看再多文献也无解，只能靠把版本摆到面前、看自己对哪个心动来逼出判断。

这两种原型形式上都是"做东西"，区别在目的。不冲突。

### 步骤 2——"好不好"的两层拆分

茫然的真正来源被诊断为：**没有判断标准**。没有标准，自测凭直觉是东一下，找被试做量表访谈也是东一下，因为量表只收数据、不告诉你"什么算赢"。

"好不好"被拆成两层：
- **第一层（设计判断，不需数据，一人可定）**：这个版本作为研究对象逻辑上立得住吗？标准是"reviewer 一句话问得倒吗"。第七轮杀掉"曼陀罗+自然 vs 曼陀罗+色轮"用的就是这个标准——这个判断力早已具备。
- **第二层（体验判断，才需要人）**：这个设计操作被试感知得到吗？标准极简："这个差异，被试不需要提示就能自己说出来吗？"

"工作东一下西一下"的真相是：把第二层的工具（量表、结构化访谈）错配到了第一层和零层（设计成不成立、操作能不能被感知）的问题上。

### 步骤 3——package 合法性带来的新迷茫

承认 package-level 合法后，反而更迷茫：在 package 下咬合根本不用单独论证，因为它是改造曼陀罗的根本机制。但随之而来的混乱想法是——"如果研究问题是『注入新意义的曼陀罗 vs 纯曼陀罗』，那【叠加】就不再是阻碍"。明知这是个坑，却说不清为什么。

坑的命名：**通过加宽实验条件，把答不上来的归因问题藏进 package。** 叠加问题没消失，只是从"组间差异"变成"实验组内部黑箱"。但关键澄清——**打包不是作弊**：package 合法的前提是研究问题必须是 package 层级、且只声称 package 层级的结论。坑不在设计里，在"问题（package）与好奇心（组件）不一致"。

### 步骤 4——"可拆解性"作为改造 vs 叠加的判据

自己推出的判据：**"单独做 X 没意义" ⟺ X 不可独立拆出 ⟺ X 是对曼陀罗的改造而非叠加 ⟺ 对照组不需要也无法给出"光 X"那一臂。**

- "曼陀罗 + X"：X 与曼陀罗各自独立成立，可拆，所以"光 X""光曼陀罗"有意义，对照组被迫拆解，叠加问题缠身。
- "改造曼陀罗"：改造离开曼陀罗就不成立（咬合是"取色-填色结构内颜色与意义的一根线"），不可拆，对照组天然是纯曼陀罗。Mantzios 慈心曼陀罗对照组就是 standard mandala，不是"叠加式慈心曼陀罗"——同一种设计。

### 步骤 5——判据被自己证伪：改造里捆着两个可分离的东西

进一步指出：改造里其实捆着**内容**（X，自然 vs 别的 Y）和**结合方式**（咬合 vs 叠加）两个东西，二者都能脱离曼陀罗被单独讨论。所以"离开曼陀罗就不成立"是假的——它们不是不可拆，是没去拆。慈心曼陀罗同样有此问题（慈心内容 vs "标注"这个动作未被控制）。

但这个"洞"不是咬合的致命缺陷，而是**所有 package 研究的解剖结构**：慈心曼陀罗、Anima、合作曼陀罗全都有。它在 artifact-centered 范式里不被当成洞，被当成边界——package 论文的契约是"我证明这个完整的东西更好，不声称是里面哪个零件起作用"。那个"哪个零件"是留给后续论文的位置。

**"咬合是设计还是变量"，取决于把研究问题范围划在哪——这个范围是研究者画的，不是设计本身决定的。** 划成 package，咬合是设计，洞在范围外；划成组件，咬合是变量，需要 2×2（内容 × 结合方式）四臂——正是第一轮砍掉的"4 组析因设计"，但这次是带着理由回来的。

### 步骤 6——4-arm 的真正死因不是复杂，是价值低

用"理论价值"而非"方法学严谨"重新衡量：4-arm 就算成功，也只是证实一个自己脑补的小设计，自然归于焦虑缓解、咬合是典型设计问题，混在一起不知贡献给哪个领域的哪个理论，无学术价值。

**这是本轮最重要的一次判断标准切换**：前七轮判断好坏一直用方法学标准（能否干净归因、reviewer 问不问得倒），本轮第一次换成理论价值标准（这个研究值不值得做）。前面所有迷茫之所以无解，部分原因是用方法学标准去解一个本质是理论价值的问题——方法学能告诉你设计干不干净，永远回答不了研究值不值得做。

### 步骤 7——叠加的致命混淆，唯独咬合免疫（用户设套验证）

用户提出反例考验：【自然叠加曼陀罗】vs【纯曼陀罗】，若前者好，无法知是自然在起作用还是组合在起作用；换【纯休息+曼陀罗】对照，结论会滑向"自然 > 休息"，曼陀罗成混淆变量。

这个分析正确，但它**精确且唯一地命中叠加，碰不到咬合**：叠加里自然是一段可独立存在的体验，正因可被单独拎出，"是自然还是组合在起作用"才有意义，自然才**能**成为混淆。咬合里没有一个叫"自然"的可独立起作用的东西——它是"颜色携带来源意义"这个属性，离开曼陀罗取色-填色结构不存在，不是组合的加数，是曼陀罗被改写后的性质。**用户用这个套，亲手为"咬合优于叠加"补上了最硬的一块砖。**

### 步骤 8——"反噬"机制的完整识别

用户的关键自我观察：**【咬合】从认识论上能与【叠加】清晰划界（两个不同研究问题），但落在方法论阶段马上变模糊，并反噬原本清晰的认识论。**

反噬的精确机制被拆解：它发生在**为咬合设计对照组的那一刻**。一旦想"咬合组要跟什么比"，大脑自动滑进 variable-centered 反射——"要证明咬合有用，得有个不咬合的对照"——这一造，就把"咬合"从"曼陀罗的内在属性"偷偷重新定义成"可拆下的变量"，于是叠加的混淆借尸还魂。**"为变量找对照"这个动作本身，把"属性"重新物化成了"变量"。**

解药（精确到动作）：**为咬合曼陀罗找对照时，绝不能问"怎么剥离咬合"，只能问"标准曼陀罗的最干净版本是什么"。对照组的角色是"改造前的原物"，不是"剥离了核心特征的版本"。**

### 步骤 9——"无懈可击设计"的执念被识破

新的纠结：能改造曼陀罗的设计有无穷变体（嵌入、咬合、未想到的），每个都要单独辩护、防不胜防；而叠加这种最简形式好辩护。

破解：**这个纠结源于一个不可能达到的标准——"让所有 reviewer 无话可说的设计"。没有任何设计能做到。** 叠加不是"攻不进来"，是有一个**致命**攻击点（分离混淆），一击毙命，少而集中的攻击点给了虚假安全感。咬合的攻击点多但**全部可辩护**（嵌入破坏心流、叠加导致分离、咬合两者兼顾），且无致命点。

**reviewer 问"为什么不用变体 X"，不是攻击设计有洞，是要求展示设计判断力。变体的存在不是弱点，对变体的取舍理由才是强项。** "被问到"被误读成了"被攻破"。研究不是建攻不破的堡垒，是养"被攻击时站得稳、答得上、且知道自己长在哪条理论谱系上"的判断力。

### 步骤 10——大炮打蚊子之问，与三个定位

疑虑：双屏自然曼陀罗技术复杂度高几个量级，若只为提升曼陀罗正念，引导/音乐/慈心曼陀罗都已做到，是不是大炮打蚊子？

**文献核查（本轮唯一一次检索）纠正了前提**：所谓"已做到"并不牢。Mantzios 2021 慈心曼陀罗的对照是慈心冥想（结论是"慈心涂色 ≈ 慈心冥想"），不是干净地证明"慈心涂色 > 标准曼陀罗正念"；AR 曼陀罗（陈 2024）主打心流而非正念。曼陀罗提升正念的实证证据"非常有限"，Mantzios 2018 那个开放问题至今未被干净合上。**不是红海，是仍在动的水。**

三个定位逐个用"技术复杂度是否成为必需"检验：
- **定位一（弱）**："自然咬合曼陀罗能提升正念"——死，与慈心同类，技术溢价无处安放。
- **定位二（强）**：具身/感官式意义注入 vs 概念/社会性意义注入是否走不同心理路径——技术复杂度是入场券。
- **定位三（强，HCI）**：把"意义的来源"做成可实时具身操作的外部交互对象——双屏即贡献本身。

### 步骤 11——定位二被用户否决：抽象层错位

用户否决定位二：在艺术疗愈/自然疗愈语境里，研究者关心的不是"意义注入"这个**形式**，而是"注入什么"的**内容**（自然/慈心）。"具身意义注入"是生造词，"意义注入→正念"这条研究线不存在。

**承认错误**：一直在往"注入的形式"（具身 vs 概念）这个上位概念抽象，以为越抽象越有理论高度，实则把用户架到了其领域不说话的抽象层，所以怎么锁都别扭——不是用户不肯锁，是给的选项悬在领域语境之外。

### 步骤 12——用户再否：目标不在"内容"，在"改造"

随即澄清更深一层：目标也不是"搞内容"，而是回到"**改造后的曼陀罗 vs 纯曼陀罗是否更好**"这个朴素问题。并捞出一个前几轮（经检索确认为 2026-05-03 那次对话）提出又放弃的机制猜想——

**通过改变任务结构打破曼陀罗传统的【心流】，颜色来自"我与自然交互的过程"这一设计，使被试不再完全沉浸于涂色本身，加入"对当下的自我知觉"（正念特征），从而可能提升正念。**

当时因"心理假设链条太复杂、验证需复杂模型、多点可能失败"而放弃，退回纯 package，结果"砍掉机制层、只留空洞形式，让复杂双屏设计变得意义不大"。

### 步骤 13——漂移的总开关：机制被藏进地下室

用户的终极自我诊断：**砍掉机制后心里那个空没补上，一直想找理论实体补，怎么补也不理想，理论不固定、方法固定，上层对齐下层导致思路漂移。**

诊断被再推一层（并被用户认可）：**不是理论不固定。是心里真正固定的是那个机制假设（打破心流→腾出空间），但不敢把它当研究问题，于是嘴上降级成"方法"（package），再去找一个"够安全"的理论外壳。机制被藏进地下室，却在楼上一个个试家具——承重墙在地下室，楼上摆什么都立不住。** 双屏的全部意义本就长在那个机制上（颜色来自"交互过程"的具身性，正是用来打破"盯着填色效果"的沉浸式心流）；砍掉机制，等于砍掉双屏的存在理由，所以才一边砍一边觉得不值得。

### 步骤 14——把吓人的长链拆短：其实只剩一环半

澄清两个被混淆的链条长度：
- 吓人的长链（六环）：虚拟自然→自然联结→正念→打破心流→注入意义→新结果。
- 05-03 已砍掉前两环（自然联结、为什么是自然，外包给文献）后，核心机制只剩**一环半**：（改造后的）曼陀罗任务结构 → 心流模式改变（降低沉浸/时间扭曲） → 给正念性自我觉察或 MW 腾出空间。

这不是需要复杂中介模型的链条，是一个"任务改造后曼陀罗心理结构发生什么变化"的**描述性/机制性问题**，用组间比较 + 子维度模式描述即可显现，正是 Macaulay 那种 mechanism-focused 研究的做法。**当初以为"砍掉机制才可行"是误判——在"空洞 package"和"六环复杂链"之间存在第三条路：一环半的、机制聚焦的、用模式描述而非中介模型支撑的研究，而这条路恰恰需要双屏、咬合、心流子维度+正念+MW 测量，所有零件第一次全部对齐。**

### 步骤 15——灵魂动词：package 够不够，取决于动词

用户追问：回到机制猜想，package（两臂）还凑效吗？

把一环半的链拆成三个可观测断点：
- **断点一**：改造后心流结构变了吗（沉浸/时间扭曲子维度下降）——package 完全够，纯组间比较。
- **断点二**：正念/MW 升了吗——package 够，组间比较。
- **断点三**：心流下降与正念/MW 上升是**同一回事**吗（"腾出空间→填上"的因果转化）——**package 照不到**，这是机制假设的灵魂，两臂给不了方向性转化。

结论：**package 够不够，取决于研究问题的动词。**
- 动词 = "改变/伴随"（描述性）：断点一+二就完整回答，package 够且干净。这正是 05-03 收缩到的版本（"心流降低+MW 上升就够清楚了"）。
- 动词 = "导致/腾出"（因果转化）：断点三是核心，package 不够，需操纵心流的设计或大样本中介——属于第二篇。

**当初砍的不是"机制假设"，是"机制假设的因果转化版（断点三）"，却错误泛化成"机制不可做"，连断点一二一起砍了——砍多了。**

### 步骤 16——样本量混淆的澄清

- 120 人是**确证性中介模型**（心流→正念路径作为预注册假设、要功效检出间接效应）的要求——属下一篇，从本篇预算移除。
- 本篇两件分析，样本都落在约 70 人（每组约 35）：
  - 主分析：2（组）×3（时间点）混合方差，确证性，检验组×时间交互（断点一二），70 多人对中等效应功效够。
  - 探索性回归：改造组内（n≈35），用心流子维度下降量预测正念/MW 升高量，**不额外加人、低功效、措辞为"初步提示"**，角色是给第二篇提供效应量估计。

**探索性回归不背高样本的债，因为它不承担确证因果的重量——这正是 04-25 分析 Macaulay 时拎清的：mechanism-focused 研究用回归而非中介、用过程变量、做探索性模式描述。** "做完方差又做回归数据要求是不是又上来"是把探索性回归误当确证性中介产生的幻觉。

## 本轮的关键判断

**判断 1（方法论认领）**：本研究走 package / artifact-centered 路线。这是一种平等、合法的科学（慈心曼陀罗、Anima、合作曼陀罗全在此路线，全发于好 venue）。package 的自由是"不必拆解机制"，**不是"可以事后挑选任意理论解释"**（后者是 HARKing）——必须事前锁定一个核心理论主张。

**判断 2（反噬准则，贴墙）**：**当对照组的设计意图是"剥离实验组的某个特征"时，就是在把 artifact 偷偷拆成 variables，认识论的清晰会被方法论反噬；当对照组的设计意图是"改造之前的标准原物"时，artifact 保持完整，认识论清晰得以保全。** 叠加致命，因为它天生把自然摆成可剥离成分，逼人走前一条路；咬合安全，因为它把自然焊死成曼陀罗的内在属性，只允许走后一条路。

**判断 3（执念识别）**：七轮无法定稿的主因不是任何设计缺陷，是"必须找到无懈可击的设计"这个不存在的标准，与 artifact-centered 路线反复打架——每当想象出某个 reviewer 的某个变体质疑，方案就"失败"被推倒。要放下的是执念，不是设计。

**判断 4（研究问题动词锁定）**：本篇动词锁定为 **"改变/伴随"**（描述性机制），不锁"导致/腾出"（因果转化）。断点三（心流下降是否导致正念升起）郑重交给第二篇。这是本轮要付的、也是用户最终需接受的让步——对机制的不舍，本质是不舍得把断点三让给下一篇。

## 本轮锁定的研究方案骨架

> 注：本骨架建立在"用户认领上述机制假设"的前提上。本轮结束时用户表示"打破心流→腾出空间先不做（不做因果中介），先验证心流是否下降、MW 是否上升，也许加上两者是否相关；中介模型留待下一篇"——即采纳描述性动词版本。

**研究问题**：用"颜色来自被试与自然的交互过程"这种方式改造曼陀罗（咬合），是否会改变曼陀罗固有的心流结构（降低盯着成品的沉浸式专注），并伴随状态正念 / 有意走神（deliberate MW）的不同模式？

**理论之家**：自然疗愈文献（外包"自然为何有效"，一句话带过）× Mantzios 慈心曼陀罗（提供"颜色赋意 → 改造曼陀罗心理机制"的结构先例）。

**对照组**：标准曼陀罗（常规调色板/色轮取色、正常填色）——即"改造前的原物"，**非**"剥离咬合的版本"。

**咬合的定位**：实验组的设计特征（artifact-centered），**非**被剥离检验的变量。叠加不采用，因为它让自然落在"颜色内容"之外、且天生带分离混淆。

**设计要素（沿用第六轮）**：双 iPad 并排；阶段一自然屏交互取色，阶段二自然屏在场 + 取色时反向反馈（颜色↔自然双向激活，机制引擎，非可选功能）；取色频率作为过程变量（exploratory）。

**主结局**：心流（FSS，**按维度报告、不看总分**，事前点名"沉浸/absorption"与"时间扭曲"为重点）、状态正念（量表选择服从机制中"正念"具体指向，待定）、MW（回溯式状态量表，需分 deliberate vs spontaneous，机制对应 deliberate MW）。

**时间点**：T1 基线 / T2 诱导后 / T3 干预后。焦虑、正念、MW 三点重复测；心流通常 T3 回溯式测一次。

**样本量**：约 70（每组约 35）。

**分析**：2×3 混合方差（确证性，组×时间交互）为主；改造组内探索性回归（心流子维度变化预测正念/MW 变化）为辅，措辞"初步提示"，为第二篇提供效应量。

**明确划给第二篇**：心流→正念的确证性中介（断点三，因果转化）、约 120 人、可操纵心流的设计。

## 工具层：MVP 决定

### 技术栈

**全网页栈**：自然屏 Three.js（或先用 2D 模拟）+ 曼陀罗屏 Canvas 2D + WebSocket 跨屏通信。**明确不用 MPC（Multipeer Connectivity）**——MPC 是正式工具阶段（追求生态效度、最佳手感、真机部署）的选择；MVP 阶段要的是"十分钟改一版、能并排切换对比版本"，MPC 会把"改一版"从刷新浏览器抬高到编译上真机。逼真度此刻完全不重要——测的是设计结构能否被感知，不是场景美不美。

技术栈的打包不对称：网页栈天然是 web，需 app 壳时用 Capacitor 包一层近乎零成本；Unity/Unreal 原生是 app，导 web（WebGL）有体积/兼容代价；原生 Swift 只能 app、无法转 web。

### 双屏 vs 单屏（用户坚持双屏，已采纳）

单屏会抹平"跨屏注意成本"这个真实变量。本研究机制高度依赖"取色时对面屏的反馈是否、以及如何把注意拉过去"——这正是要观察的东西，单屏测不出。故 MVP 即用真双屏。

### MVP 形态（清单 + 修订）

1. 粗略自然场景，2D 先做（最快；逼真度对机制不贡献，取最低档，能辨认来源即可）。
2. 内置交互点，函数化（带入不同 model id），第一版先接 3-4 个验证流程，扩到 12 个是改数组的事。
3. **点击提示——改为可调旋钮，不定死**：做两个微版本——(a) 固定位置 + 明确提示；(b) 固定位置 + 弱吸引（元素轻微摇曳/微光，被"吸引着碰"而非"指示着点"）。**这是要测的变量，不是要定的常数**——因为强提示会把"与自然交互"降格成"执行采集任务"，伤及机制本身（自变量到底是"交互"还是"完成任务"）。剂量可控用软引导（"找到并触碰吸引你的元素，大约十来个"）保证，不必靠强提示。
4. 点击反馈：精灵粒子可以，但**克制**（华丽的收集爽感会强化心流，与抽离机制反向）。
5. 固定曼陀罗，点击填色，含空颜料盒。
6. 颜料盒填入**元素局部图（带来源形象的色块，非纯色块）**，持续可见——维持"来源持续在场"，优于一次性飘动画。
7. 取色时自然屏反向反馈（机制引擎）：粒子可以但**朴素、清晰指向来源**（那朵花动一下/亮一下），不喧宾夺主。

**关于"飘动画"的判断**：去掉一次性飘动画，改用"安静的来源标记（色块带来源图标）+ 持续可见 + 取色时反向激活"。若第一版来源感不够，加法方向是**加强反向反馈的显著度**（强化来源召回），**不是**加飘动画（强化收集爽感、帮倒忙）。

### 原型的唯一任务

MVP 的唯一目的：判断**"咬合机制在体验里到底存不存在"**——颜色携带来源 → 填色时唤起 → 腾出觉察/反思空间，这条链第一环（被试是否意识到颜色有来源）成不成立。这是"读一百篇文献、想第八轮第九轮都给不了答案、只有指头戳屏幕才知道"的问题。

**第八轮与第七轮的关键差异**：第七轮悬而未决的是"研究问题与对照组的对齐"（结构性问题，原型解决不了，故当时不做原型是对的）；本轮悬而未决的是"咬合机制在真实体验里立不立得住"（体验性问题，**只有原型能回答**）。悬置点的性质从结构问题变成了体验问题——故现在做原型不仅合理，且不做反而错。

## 关于自测与评估

**自测的效度限制（用户自己识别，已采纳）**：用户是从研究问题到工程的唯一源头，对每个设计意图了如指掌，已被设计彻底污染——"记得来源""反馈作用""是否吸引"这类体验判断，用户自测会系统性高估机制强度（"知道颜色有来源"是因为是自己写的逻辑）。这不是态度问题，是结构性的不可能。这些体验判断**留给那两个被试，一个字都别自己填**。

**自测真正能贡献的两样（被污染身份反而看得更准）**：
1. **工程层面"机制承不承载得动"**：取色→反馈延迟会不会大到让"颜色↔来源"连接在时间上断掉；真实两屏物理距离下余光够不够得着、还是必须转头。确保真被试若没感到来源，是因为机制弱、而非反馈卡顿。
2. **意图与实现的落差**："咦，和我想的不一样"的瞬间——只有造它的人有"原本该怎样"的参照，被试没有。这是污染观察者唯一独有的真信号。

**被试测试**：找 2 人，结果只做定性探索，问"在两个任务中，那种投入任务的感觉有没有性质上的不同""刚才点那些东西，感觉像在探索还是像在完成任务"——开放、不提示。这是**操作可感知性测试（manipulation perceptibility check）**，不是 pilot、不是 efficacy test，不关心干预有没有效，只关心操作存不存在。FSS/SMS/MW 等结局量表此步全不用。

**预期管理**：自测是 n=1 且最有偏的 1，给的不是"机制成立"的证据，只是"值不值得往两个真被试上投"的信号。三种结果都正常——隐约出现→值得找人测；完全没有→重大但有用的负发现（咬合需重新设计）；似有似无→正是该找人测的状态。

## 本轮明确的下一步

1. **动手做 MVP**（全网页栈、真双屏、WebSocket）。用户自行开发（前期可自己上手，非必须等学生）。
2. 用户自测，但**只带回两样反馈**：工程上机制承不承载得动（延迟/距离/同步有没有掐死连接）、哪里与设计意图不一样。体验判断（来源感、抽离、反馈、吸引）不自填，留给被试。
3. 找 2 人做定性可感知性测试。
4. 据反馈决定：回到机制假设定稿（描述性版本）、退回朴素 package、或重新设计咬合。

## 本轮的方法论收获

**收获 1——原型的两种性质**：逃避式原型（用工程进度冒充研究进展，第七轮所反对）vs 生成式原型（用做东西产生还没有的判断）。区别在目的不在形式。当未决问题是"我到底想要哪个"而非"哪个答案对"时，文献无解，只能靠生成式原型逼出判断。

**收获 2——判断标准的层级与工具错配**：设计成不成立（零层，标准是"reviewer 问得倒吗"，一人可定）/ 操作能否被感知（第一层，标准是"被试不提示能否自己说出差异"，需人但极轻）/ 干预有没有效（第二层，需正式量表）——三层各有其工具。"东一下西一下"的根源是把高层工具错配到低层问题。

**收获 3——package 的自由边界**：package 免于"拆解机制"的负担，但不免除"事前锁定一个核心理论主张"的义务。自由在"不拆零件"，不在"事后挑解释"。多结局的合法探索与 HARKing 的唯一区别是"事前声明"。

**收获 4——反噬机制与对照组准则**：见判断 2。"为变量找对照"这个动作本身会把"属性"物化成"变量"。对照组的正确角色是"改造前的原物"，不是"剥离了核心特征的版本"。

**收获 5——站得住 ≠ 无懈可击**：没有任何设计能让所有 reviewer 无话可说。叠加的"好辩护"是假象（它有一个致命攻击点）。站得住的设计是"被攻击时答得上、且长在清晰理论谱系上"的设计。reviewer 问变体是要求展示判断力，不是宣告设计有洞。

**收获 6——两把尺子（方法学严谨 vs 理论价值）**：方法学能判断设计干不干净，永远回答不了研究值不值得做。4-arm 方法学最干净却该死，因为理论价值低；2-arm 方法学更糙却更值，因为接住了真问题。迷茫常源于用方法学尺子量一个本质是理论价值的问题。

**收获 7——动词决定 package 够不够**：研究问题的灵魂动词（"改变/伴随" vs "导致/腾出"）决定两臂 package 够不够、样本要 70 还是 120。不是 package 限制了能问什么，是动词与工具必须对齐。工具（两臂）配不上野心（因果）时，package 才显得空洞。

**收获 8——机制不该藏进地下室**：当一个真正相信的机制假设因"怕复杂、会失败"被降格藏起、改去找"安全理论"填空时，那个空永远填不上——因为设计本就为那个机制量身打造，别的理论套上去都对不齐。漂移的解药不是找新理论，是认领被藏起来的那个机制（并把它的因果版本诚实地让给下一篇）。
