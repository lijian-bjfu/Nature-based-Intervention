# 数据与分析：项目结构与使用规范

本文件说明项目主目录下 `data/`（数据）与 `analysis/`（分析）两个文件夹的结构和使用原则。它们与 `研究思路/` 平级。

各数据来源的变量说明不在这里：APP 数据见《研究思路/实验记录-埋点.md》附A；问卷见《研究思路/实验记录-问卷草稿.md》；生理数据待定。全部来源定稿后，另做一份完整的数据查阅表。

---

## 一、原则

**1. 原始数据只读，派生数据可重建。**
采集到的文件原样拷入对应数据集的 `raw/`，此后永不修改。清理、格式转换、指标计算的结果都由脚本生成，写入对应数据集的 `derived/`，删除后可以重跑得到。任何一步算错，都能回到原始数据重新来。

**2. 正式数据与测试数据绝对隔离；数据按"数据集 → 来源 → 被试"组织。**
正式实验数据单独放在 `data/main/`，其中只有正式数据。预实验和各类开发测试放在 `data/pilot_and_test/` 下，各占一个子文件夹。哪些数据属于正式实验，由它所在的文件夹决定，不靠任何表格标记，避免人工维护出错。每个数据集内按来源分文件夹；被试与场次的命名沿用 LSL 文件的写法（`sub-P040_ses-S001`），不同来源之间按编号对应。

**3. 分析按工程流程组织，来源作为每一步里的子文件夹。**
每一步对所有来源使用同一套规则，前一步的输出是后一步的输入；哪一步出错就回到哪一步重跑。

**4. 路径只在一处配置。**
脚本一律通过 `analysis/lib/paths.py` 取路径，不在脚本里写死。读取 APP 数据一律用 `analysis/lib/app_io.py`（它关掉了 pandas 把 "None" 等字符串当成缺失值的默认行为）。

## 二、data/ 数据

```
data/
├── main/                      正式实验（只有正式数据）
│   ├── participants.csv       被试表：编号、场次、组别、日期等个人与分组信息
│   ├── raw/                   只读，原样拷入
│   │   ├── app/               iPad 拷出的 NBI_Data，每进入一次模块一个文件夹：sub-P040_ses-S001_mod-Interactive_run-001
│   │   ├── physio/            PhysicoBridge / LSL 的原始文件
│   │   ├── questionnaire/     问卷平台导出的原文件
│   │   ├── interview/         访谈转录
│   │   └── session_notes/     实验记录单（含"异常情况"一栏）
│   └── derived/               脚本生成，按流程步骤分子文件夹：derived/02_clean/、derived/04_features/ …
└── pilot_and_test/            预实验与开发测试
    ├── pilot/                 预实验，结构与 main/ 相同（含自己的 participants.csv）
    └── logging_test/          埋点开发测试：raw/app/ 与 derived/
```

- **数据集**：脚本里用名字指定数据集——`main`、`pilot`、`logging_test`——由 `lib/paths.py` 换算成文件夹，不写路径。以后新增一类测试，在 `pilot_and_test/` 下加一个子文件夹，并在 `paths.py` 里登记一个名字。
- **participants.csv**：只记被试的个人与分组信息，每个被试一行。列：`subject`（编号）、`session`（场次）、`group`（1 实验组 / 2 对照组）、`date`、`notes`。不记数据属于哪个阶段（由文件夹决定）；排除哪些被试、为什么排除，由 `02_clean` 的排除规则处理并记录。
- **采集位置与本目录的关系**：APP 在编辑器里写到 Unity 工程的 `Interaction/Logs~/NBI_Data/`，在 iPad 上写到 APP 文稿目录的 `NBI_Data/`。这些只是采集位置；拷入对应数据集的 `raw/app/` 之后，分析只读这里。`NBI_Data/Debug/` 里的调试日志一并拷入，但不进入分析。
- **身份信息**：姓名、联系方式、知情同意书、录音等能识别个人的材料不放在本目录。

## 三、analysis/ 分析

```
analysis/
├── README.md        本文件
├── lib/             共用：paths.py（路径）、app_io.py（读取 APP 数据）
├── 01_import/       导入：从采集位置拷入 raw，核对是否齐全（如 session.csv 是否有结束时刻）
├── 02_clean/        清理：类型、缺失、异常值标记、排除规则
├── 03_format/       格式：统一成标准长表（列名、单位、时间轴一致）
├── 04_features/     指标：量表计分、HRV、埋点指标
├── 05_integrate/    整合：按被试把各来源合成一张分析用的宽表
├── 06_analysis/     分析：describe/（描述）、stats/（统计检验）
└── 07_report/       报告：论文用的表和图
```

- 每一步下按来源分子文件夹（`app/`、`physio/`、`questionnaire/`、`interview/`），需要时再加。
- 01–05 步的输出写到对应数据集的 `derived/<步骤>/`，可删可重建。
- 06、07 步的图、表、报告与生成它们的脚本放在同一文件夹，不放 /tmp，保证可复现。
- 指标的定义与原理写在研究文档里（埋点指标写在《实验记录-埋点.md》），代码只实现文档已定的内容。

## 四、分析纪律

- 引用数值时写明字段名（如 `tap.block_type`），避免同名不同义。
- 空间分布必须出图，不能只给坐标范围和表格。
- 网格覆盖率对网格原点位置非常敏感，不用于被试间排名。
- 不用被试自己的轨迹生成基准再拿被试与之比较（循环参照）；基准取场景设计对象。
- 访谈材料有自己的质量标准，不是定量结果的佐证材料：先独立编码（说话人、时间、主题、原话、是主动提起还是追问后才说、解释边界），再与日志交叉对照；不为已有结论寻找引语。
