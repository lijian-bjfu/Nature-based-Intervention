# 打包成不依赖 Python 的可执行文件

发给学生/助研用的时候，不用让他们装 Python、不用给源码文件夹，打包成一个独立的可执行
文件（Mac 下是裸的可执行文件，Windows 下是 `.exe`），双击就能跑。

## 怎么打包

- **Mac**：`./build_mac.sh`，生成 `dist_mac/nbi_flow_system`。
- **Windows**：双击 `build_win.bat`（或者命令提示符里跑），生成 `dist_win\nbi_flow_system.exe`。

两边都要先在**打包这台电脑**上装好 Python 3（随便哪个 3.10+ 版本）——这是打包这一步
才需要的，脚本会自动装好 PyInstaller。生成出来的那个文件本身不依赖 Python，发给别人
的电脑上不用装任何东西。

打包没法跨平台：Mac 上只能打出 Mac 能跑的版本，Windows 上只能打出 Windows 能跑的版本。
实验室那台 Windows 笔记本上要跑一次 `build_win.bat`，才能拿到 Windows 的 `.exe`。

每次改了 `流程单系统/` 下的代码（`config.py`、`app/*.py`、`run.py`），都要重新跑一次
打包脚本，之前生成的可执行文件不会自动更新。

## 发给别人之前

1. 自己先双击试跑一次，确认能正常打开、浏览器会自动弹出设置页。
2. 把生成的那一个文件（`nbi_flow_system` 或 `nbi_flow_system.exe`）直接发过去就行，
   不用带 `data/`、`app_runtime/` 这些——对方那边双击运行时，会在这个文件旁边自动
   生成全新的空 `data/` 文件夹，不会带着你测试时产生的数据过去。
3. **第一次双击可能被系统拦住**，这是正常的，因为这个文件没有花钱买开发者证书签名：
   - Mac：会提示"无法打开，因为无法验证开发者"。解决：右键（或按住 Control）点这个
     文件 → 打开，在弹出的提示里再点一次"打开"；或者去"系统设置 → 隐私与安全性"，
     底部会有一条"仍要打开"。
   - Windows：会弹出"Windows 已保护你的电脑"（SmartScreen）。解决：点"更多信息"，
     再点"仍要运行"。
   这个拦截只在第一次运行时出现，之后正常双击就行；需要提前告诉用它的学生这是正常
   现象，不是文件坏了。

## 运行方式不影响数据格式

打包成可执行文件只是换了个启动方式，程序本身的逻辑、页面、数据格式（`questionnaires.csv`、
`log.csv`、`notes.txt`）跟用 `python3 run.py` 跑完全一样。`config.py` 里的参数（运行
模式、端口、各环节默认时长）在打包的时候就固定进这个文件了，改完 `config.py` 要重新
打包才会生效——不像各环节时长那样能在"设置页"临时调整。
